# Task 013 — `GET /me`

**Status: built 2026-10-23, PR pending. Verified locally: 4 new integration tests pass (and fail when seller is given backoffice's store list); local Go on a fixture database with both apps against it: signed out `/` goes to `/login`; seller shows Seller A, Tenant A, its two stores (default first); backoffice shows all three of A's stores, the closed one marked; a profile language of `id` switches the app once and is saved; `/me` is requested once, by `index.html`; Sign out deletes the session row and clears the cookie, saved user and cache; another user's session on the same phone clears the cache and reloads as them. `schema.sql` re-dumped (staging has the sessions table). First screen 124.9 KB. The preview can only show home once this is on `staging` (previews use staging's API, which gets `/me` on merge).**

## The goal

One call tells an app who is signed in: the user, their tenants and their stores. The app draws it from the phone's saved copy at once, sends a signed-out user to `/login` by itself, and home shows who is signed in instead of the status card alone.
RFC: Build order Step 13; principle 3 (one startup call replaces the proxy and the layouts); "`/me` starts with the page".

## The plan

### Go

1. **`GET /me`**, `auth.SignedIn`, in `internal/handler/me.go`, shapes in `internal/contract/me.go`:

    ```
    user:    id, email, fullName, role, avatarUrl, language
    tenants: id, slug, name, payFrequency,
             stores: id, name, status, openTime, closeTime, isDefault
    ```

    **Which stores depends on the app** (the session's `app`), as the old apps did:
    - **seller:** the stores the user is assigned to (`user_store_assignments`), with `isDefault`
    - **backoffice:** every store of the tenant, demo and retired included (the old `listTenantStores`); `isDefault` from the admin's own assignments

    Tenants are the user's `user_tenant_assignments`. A user with none gets `tenants: []`; the app shows "no tenant" (as the old `/unauthorized?reason=no-tenant`).

2. **Queries** in `db/queries/me.sql`: `GetMe`, `ListUserTenants`, `ListAssignedStores`, `ListTenantStores`. Three round trips at most, run in parallel off one pool
3. **Tests**, `tests/integration/me_test.go`, with stores added to `tests/fixtures/base.sql`:
    - seller@a sees tenant A and only their assigned stores, never tenant B's
    - admin@a in backoffice sees every store of A, retired ones included
    - a user with no tenant gets `tenants: []`
    - no session: 401 `not_signed_in` (the permission test covers the rule itself)

### Apps (shared, in `packages/`)

4. **`useMe()`** in `packages/api-client`, over `$api`, `STALE.COOL`; saved with the rest of the query cache, so a reopen draws the last `/me` before the network answers
5. **The saved cache becomes per user, as Step 14 planned:** the last user's id is kept in `localStorage` (`tea-pos:user`) and picks the cache key at startup. When `/me` answers with another user, the cache is cleared first. Sign-out clears it too
6. **Signed out:** `/me` answers 401, and the existing `api.use` sends the app to `/login`. Nothing new needed
7. **Home** (`packages/shell/HomeScreen.tsx`, both apps): avatar, name and role, the tenant, its stores (default first). A **Sign out** button (`POST /auth/logout`, then clear the cache and go to `/login`). The status card stays below it, smaller, until a real home screen replaces it
8. **`/me` starts with the page** (RFC): a few bytes of inline script in `index.html` start `fetch("/api/me")` while the JavaScript downloads, and `useMe()`'s first load takes that response instead of asking again. One round trip saved on every open, several hundred ms on Slow 4G. Measured on the preview at 20× CPU
9. **Language** as decided below (seller only)
10. **Words** in `en.json` and `id.json` (`home.*`), backoffice English only

## Decided in review (2026-10-23)

1. **No flags yet.** No v2 screen reads one, and they need `posthog-go` and a PostHog key; they come with the first flagged feature
2. **Admins see only tenants they are assigned to.** The old admin app's "super admin" bypass stays out; Step 12's tenant check already works this way
3. **Language: the profile wins, the phone keeps a copy** (seller; backoffice is English only). `/me`'s `language` is saved on the phone (`tea-pos:locale`, which `pickLocale` reads), so every open picks it before `/me` answers, with no flicker. If it was changed elsewhere, `/me` disagrees once: the app switches and saves it. The language switcher (a later step) writes the profile
